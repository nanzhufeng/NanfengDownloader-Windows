## 2. 当前产品合同

### 第一用户任务

用户粘贴一个抖音或 YouTube 单视频、作者、频道或播放列表链接，软件正确识别链接语义，生成可选择队列，并将仍被勾选的内容下载到按平台和作者组织的本地目录。

### 成功定义

- 单视频只加入一条，不扩展成整个作者或频道。
- 作者、频道或播放列表读取到目标主体的作品，不混入推荐内容或其他作者。
- 用户可以逐项选择和设置分辨率；执行瞬间未勾选的条目不下载。
- 输出是真实有效媒体，不是空文件、HTML、JSON 或错误占位文件。
- 文件按平台和作者组织，文件名优先为发布时间加标题。
- 已存在文件快速跳过；临时网络问题可重试或等待恢复；权限与风控问题给出可执行提示。
- 完成、失败、已跳过、等待网络、停止等状态与真实执行一致。

### 权限边界

- 支持公开内容和登录后当前账号本来有权限访问的内容。
- 不绕过会员、付费、DRM、私密内容或第三方平台访问控制。
- 不在软件内保存账号密码；登录状态来自软件专用浏览器资料与 Cookie。

## 3. 当前技术与所有权

| 概念 | 当前唯一所有者/入口 | 责任边界 |

| 通用媒体下载 | `app/downloader.py` | yt-dlp 参数、格式、重试、速度、进度、命名与输出验证 |
| YouTube 链接语义与列表 | `app/catalog.py` | 单视频/频道/播放列表分类与目录读取 |

| 软件内登录资料 | `app/auth_profile.py` | 浏览器资料目录、登录窗口、Cookie 导出和旧目录兼容 |

## 5. UI 与交互的稳定结论

### 已确认方向

- 第一屏直接是下载工作台，不做营销首页。
- 左侧仅承载品牌、平台、流程和固定工具入口；不保留无功能导航。
- 主区按“登录 -> 保存位置 -> 分辨率 -> 链接 -> 智能读取 -> 勾选下载”排序。
- 中央列表是主要工作面，所有表头、文本、状态、复选框和行内选项默认居中。
- 选择与状态必须分列；状态使用语义色区分等待、下载中、完成、失败、已跳过、等待联网和停止。
- 标题、作者和链接过长时提供完整悬停信息；标题和链接可点击复制并给出不改变布局高度的反馈。
- 控件组宽度统一，登录平台分开，重复的“加入队列/读取列表”合并为智能读取。
- 颜色用于任务语义：主操作、抖音、YouTube、保存、读取、停止各自可区分；不以大量装饰色替代层级。
- 图标属于独立品牌资产：应用名称变化不自动授权修改图标内文字。

### 跨项目提炼

1. 工具 UI 的第一屏应呈现真实工作流，而不是功能介绍。
2. 先稳定内容层级和动态区域尺寸，再加动画；提示不能引起窗口或主表跳动。
3. 列表默认居中是用户明确长期偏好，但长正文在其他产品中仍应根据可读性判断，不机械推广。
4. 状态颜色必须和状态机一一对应，不能只改变文案。
5. 参考图只能定义视觉目标；最终验收必须覆盖同视口交互和真实功能。

## 6. 功能、状态与架构经验

- “智能读取”是唯一业务入口，但其内部第一步必须做链接语义分类；统一入口不等于统一处理路径。
- 目录项状态至少区分等待、下载中、完成、失败、已跳过、等待网络和已停止；选择态不是业务状态。
- 队列快照适合排序，但是否执行必须读取当前用户选择，避免旧快照覆盖交互。
- 网络错误、权限错误、验证码、用户停止和内容不存在必须是不同结构化原因。
- 登录资料、下载目录索引、队列状态和单条进度各有不同生命周期，不能塞进一个无边界全局状态。
- 第三方解析器只提供内容证据；最终“可下载/需登录/需等待/失败”的结果由统一下载用例归类。
- 兼容旧登录资料目录属于数据迁移合同；不能因品牌重命名让用户无提示丢失会话。

## 7. 性能与可观测性经验

- 性能优化先定位瓶颈：目录发现、重复检测、网络格式、分片并发、合并转码或 UI 刷新必须分别测量。
- 批量重复检测使用一次预扫描和内存索引，避免每项重复遍历目录或联网。
- 下载并发需要自适应：提高分片并发可以提升吞吐，也可能触发 403/429；遇到限流应降并发，不应无限重试。
- 速度、进度、剩余时间和当前阶段要来自同一次任务状态；未知时显示未知，不编造稳定 ETA。
- 性能完成证据应记录固定样本、线路、时间、分辨率、持续吞吐和失败率；单次峰值只用于诊断。

## 8. 账号、平台与外部限制

- 公开内容优先免登录是产品目标，不是平台承诺。
- 软件内登录资料比读取用户日常浏览器数据库更稳定，也避免要求用户关闭浏览器。
- 登录成功必须以可用账号 Cookie 或目标内容访问结果判断，不能以“浏览器窗口打开过”判断。
- Cookie、Token、账号数据和浏览器资料目录都不得进入 Git、共享 Skill、普通日志或长期记忆。
- 外部平台风控、地区限制、IP 信誉和接口变化要显示为外部约束；应用只能提供降级路径和可执行提示。

## 9. 被否定方案与禁止项

| 被否定做法 | 失败原因 | 防回归资产 |
|---|---|---|
| 单视频自动扩展作者/频道 | 违背链接本身语义，制造不可控批量 | 单条/作者/频道分类契约测试 |
| 把推荐流当作者分页 | 队列混入其他主体内容 | 目标主体身份过滤与真实作者页样本 |
| 只在批量开始时读取勾选 | 后续取消不生效 | 每项执行前选择态合同 |
| 以返回成功代替媒体校验 | 产生空文件或伪视频 | 输出存在、大小、内容类型与可探测媒体检查 |
| 每条都重新扫描目录 | 大列表跳过效率差 | 批次预索引与复杂度回归 |
| 强制读取日常 Chrome Cookie | Cookie 数据库占用且体验差 | 软件专用登录资料与分平台登录入口 |
| 为免登录承诺平台永远可用 | 忽略平台风控与网络限制 | 错误分类、真实服务验收和边界文案 |
| 用构建或截图宣称功能完成 | 没有证明真实下载链路 | 分层验收矩阵 |
| 品牌重命名时顺手改图标文字 | 名称与品牌资产不是同一授权范围 | 交付清单分别核对产品名与图标资产 |
| 在 dirty 混合仓库直接发布 | 易把 Android/Mac/临时文件带入 Windows | 独立 staging、文件清单和发布检查 |

## 10. A-E 分类

### A. 项目专属事实

- “南枫下载”、Windows PySide6 技术栈、模块路径、Release、哈希、默认 `D:\南枫下载`、旧登录目录兼容和平台下载规则。
- 这些事实只保存在本项目上下文、测试和交付记录中，不进入通用 Skill 正文。

### B. 跨项目可复用规则

- 冻结唯一最终基准并排除旧稿。
- 建立“反馈—根因—实现—分层验证—风险”矩阵。
- 一个概念一个所有者和公开入口；在首个语义分叉修复。
- 选择态、业务状态和执行快照分开。
- 把重复反馈变为合同、测试、检查或截图基线。
- 性能报告使用固定环境和持续数据，不用峰值冒充完成。
- 交付分别验证产品名、图标、版本、依赖、启动、升级、数据保留、包名和平台隔离。

### C. 经授权写入的长期偏好

- 用户说“正式沉淀”时，默认执行完整证据化流程，不只生成总结。
- 只把明确表达、跨项目可复用的偏好写入长期记忆；项目事实和秘密留在项目内。
- 当前任务内保持单主代理、顺序执行、增量读取、最小充分验证。

### D. 平台约束

- Windows 的 D 盘、PyInstaller、`.bat`、Cookie 文件占用和路径长度规则不推广到 macOS、Android 或 Web。
- macOS `.app` 必须在 Mac 本机构建、签名和验证。
- Android 的折叠屏尺寸、系统媒体目录、后台任务和权限模型属于 Android 专属合同。

### E. 尚未验证的推测

- 当前并行分片参数在不同网络、分辨率和地区是否始终优于保守设置。
- 抖音页面结构变化后的作者过滤、图文合成和浏览器捕获稳定性。
- 软件内登录资料在所有 Chrome/Edge 版本升级后的长期兼容性。
- 当前 UI 的键盘导航、屏幕阅读器和高 DPI 全覆盖程度。

- `docs/nanzhufeng-video-downloader-development-context-for-chatgpt.md` 保存了大量历史过程和旧 `dist` 路径；它可用于理解失败经验，当前发布事实以 `docs/context.md` 和本审计为准。
- 当前 Git 最新提交是 Android 工作台文档提交，而 Windows 成品主要存在于 dirty 工作区和独立发布 staging；不能以 `master` 最新提交直接重建并宣称等同于已发布 Windows 包。
- 当前根目录同时含 Windows、Mac 和 Android 资料。平台文件可以共存，但测试、构建、交付和真实验证结论必须按平台隔离。

## 13. 下轮优先事项

1. 扩展真实服务矩阵到 1080p、最佳画质、MP3、播放列表分页和登录后权限内容。
2. 在可控环境中执行一次真实断网—恢复下载，并记录恢复耗时和断点续传行为。
3. 对 GUI 大文件停止做人工计时，确认停止反馈和临时文件清理。
4. Windows 后续开发切换到独立源码仓库，发布流程不再从混合根目录取文件。
