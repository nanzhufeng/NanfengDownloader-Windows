### B站多 P 选集

- 浏览器顶部地址 `https://www.bilibili.com/video/BV1YGNm6MEPq/...` 经“智能读取”展开为 6 条；
- 队列链接严格对应 `?p=1` 至 `?p=6`，作者均为“AI应用全栈开发”；
- 实际下载第 6 P 只生成当前分 P，文件名以 `P06` 开头；
- 输出文件 10,702,316 字节、378.603 秒，通过 FFprobe 与 FFmpeg 数据包扫描；
- 普通单 P 视频仍保持一条队列项，不会错误扩展。

### 本轮发现并修复的问题

首次执行时，小红书长视频的 CDN 声明总长度为 17,975,450 字节，但连接在
3,145,728 字节提前结束。旧逻辑将 EOF 误判为完成，FFprobe 仍能读出 MP4
头部时长，只有 FFmpeg 数据包扫描能确认 `corrupt input packet`。

修复后：

- 按 `Content-Length / Content-Range` 检查完整字节数；
- 连接提前结束时使用 HTTP Range 最多续传 5 次；
- 正常视频先写 `.downloading.mp4`，完整性验证通过后再原子改为正式文件名；
- 既有同名文件必须先通过媒体校验才会跳过；
- 最终验证从“仅 FFprobe 元数据”提升为“FFprobe + FFmpeg 全数据包扫描”。

结构化证据：

- `docs/verification/bilibili-xiaohongshu-long-short-latest.json`
- `docs/verification/xiaohongshu-long-resume-latest.json`
