# 抖音连接中断与断点续传回归验证

> 日期：2026-08-11
> 范围：抖音直连媒体下载、连接重置、HTTP Range 续传和最终媒体完整性校验。

## 原始问题

- 作品：`https://www.douyin.com/video/7672733816821173547`
- 原始错误：下载结果可被 FFprobe 读取，但 FFmpeg 全数据包扫描报告文件不完整。
- 原实现只循环读取单次 HTTP 响应，没有对 CDN 连接重置、提前 EOF 或内容长度不足执行续传。
- 失败校验会删除不完整文件，因此正式输出目录中不会保留损坏 MP4。

## 根因证据

- 同一作品的隔离真实下载首次建连直接出现 `WinError 10054`。
- 修复后同一下载过程记录到 4 次连接中断，随后通过断点续传完成。
- 这证明原错误来自抖音 CDN 的瞬时连接中断，而不是标题、保存路径或 FFmpeg 对正常文件的误判。

## 修复

- 抖音媒体请求增加有限连接重试，最多 8 次，不无限请求。
- 已收到部分数据且服务器提供总长度时，使用 `Range: bytes=<offset>-` 继续下载。
- CDN 忽略 Range 并返回完整 `200` 响应时，从头覆盖文件，禁止把完整响应追加到半文件后面。
- 达到重试上限或仍存在内容长度差异时删除半文件并明确失败。
- FFmpeg 数据包错误摘要优先保留实际错误行，不再被超长文件路径截断。

## 验证结果

- 同一真实作品下载完成：`38245410` 字节。
- FFprobe 格式：`mov,mp4,m4a,3gp,3g2,mj2`。
- 视频时长：`477.006` 秒。
- FFmpeg 全数据包扫描通过。
- 4 项抖音续传定向测试通过：首次连接重置、提前 EOF、Range 忽略安全重下、连续 5 次重置后恢复。
- 媒体错误摘要回归测试通过。

## 边界

- 当前正式 GitHub Release `v2026.08.10-windows` 尚不包含本修复；源码/BAT 版包含。
- 平台持续不可达或连续 8 次失败仍会停止，并保留清晰错误，不会无限重试。
