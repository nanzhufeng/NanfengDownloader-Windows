# HLS 分片传输对比：未达到 50 MiB/s

同一来源清单，全部 484 个分片，在内存读取，不保存影片。比较脚本为 `scripts/benchmark_hls_transport.py`。这不是 GUI 完整下载：不含播放器解析、磁盘写入、合并和媒体验证。

|顺序|客户端|并发|结果|
|---|---|---|---|
|1|urllib，每次请求新连接|16|URLError，未完成|
|2|requests，每线程 Session 复用|16|283487080 字节，20.008 秒，13.513 MiB/s|
|3|requests，每线程 Session 复用|8|283487080 字节，27.768 秒，9.736 MiB/s|
|4|requests，每线程 Session 复用|16|ConnectionError，未完成|

两次成功结果的按分片 SHA-256 再聚合摘要一致：`0fed2da573157963aed5c42af57efb3763b206c8cab184211ac5ee4b0861443a`。

结论：16 并发的一次成功样本快于 8，但复测失败；无法证明稳定加速，更未达到 50 MiB/s。现有 yt-dlp 已有 Requests Session 支持，不应仅凭“连接复用”换掉成熟的 HLS 合并/断点/解密实现。此次保留生产下载配置，不加入未经验证的新传输器。无法从这些结果单独判定瓶颈是源站还是用户线路。
